# Автоматические копии задач

Схема: сервер Vercel по расписанию или по кнопке в настройках читает задачи из Firestore и сохраняет приватный JSON в Vercel Blob. Затем он вызывает личный Google Apps Script, который скачивает **именно эту** копию и сохраняет её в отдельную папку вашего Google Drive. Ежедневному режиму не нужны включённый телефон или открытая вкладка браузера.

Код сам по себе не включает резервное копирование: сначала нужно подключить хранилище и задать секреты. До завершения шагов ниже автоматических копий **нет**.

## 1. Vercel Blob

1. В проекте сайта `reminder-amber-theta.vercel.app` откройте Vercel → Storage, создайте Blob store с доступом **Private** и подключите к этому проекту. Убедитесь, что в Production появилась переменная `BLOB_READ_WRITE_TOKEN`.
2. В Settings → Environment Variables задайте `CRON_SECRET` для Production: случайная строка не короче 32 символов. Не записывайте секрет в GitHub, код, чат или публичные документы. Если переменные меняли после последнего деплоя, выполните Redeploy.
3. Убедитесь, что в Production уже существуют `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL` и `FIREBASE_PRIVATE_KEY` для проекта Firebase `reminder-60e25`. Не подменяйте их локальными/тестовыми ключами.
4. После деплоя задание `/api/cron/backup-tasks` срабатывает ежедневно около 03:00 UTC, если ежедневный режим включён в настройках приложения. Оно сохраняет только непустую, пригодную для импорта копию и проверяет размер загруженного файла перед очисткой. Если число задач резко упало, новая копия сохранится, но старые не будут очищаться автоматически.
5. В Storage проверьте приватный файл `todo-interval/automatic/YYYY-MM-DD.json`. В журнале запуска должна быть запись об успешном вызове; HTTP 503 означает отсутствие настройки, 500 — ошибку чтения или записи. Пока не увидели настоящий файл и успешный запуск, считайте защиту **неактивной**.

Очистка Vercel затрагивает только файлы приложения с указанным именем в префиксе `todo-interval/automatic/`: максимум 30 копий или 200 МБ, но минимум три последних сохраняются даже при превышении размера. Если лимит бесплатного плана достигнут, очередная запись может не пройти — в этом случае старые копии намеренно не удаляются.

## 2. Личный Google Drive

1. Откройте [Google Apps Script](https://script.google.com/), создайте личный проект и вставьте код из [`google-drive-backup.gs`](google-drive-backup.gs). Не делитесь редактором скрипта и не публикуйте его код в другом месте.
2. В Project Settings → Script properties добавьте `BACKUP_TOKEN` со **значением того же** `CRON_SECRET`, что задан в Vercel. Этот секрет даёт доступ к полным названиям, описаниям и срокам задач, поэтому храните его только в Script properties.
3. Запустите `backupToDrive()` вручную один раз после появления первой копии Vercel и разрешите доступ к Drive и внешним запросам своему скрипту. Затем Deploy → New deployment → Web app: **Execute as me**, **Who has access: Anyone**. Адрес `/exec` доступен для вызова извне, но `doPost` выполняет копирование только при правильном секрете и допустимом имени файла. Не помещайте секрет в URL.
4. В настройках проекта Vercel добавьте секретную переменную `GOOGLE_BACKUP_WEBAPP_URL` для Production со значением полного адреса `/exec` и сделайте Redeploy. URL не содержит `BACKUP_TOKEN`. Если раньше вы запускали старый `installDailyBackup()`, один раз запустите `removeLegacyDailyBackupTrigger()`; теперь обе копии запускает Vercel по одному расписанию.
5. В настройках веба или APK введите `CRON_SECRET`, нажмите «Проверить подключение» → «Создать копию сейчас». Убедитесь, что сообщение подтверждает **оба** хранилища, а в папке `To-Do Interval Backups` появился JSON-файл. Скрипт сохраняет ID своей папки в Script properties как `BACKUP_FOLDER_ID`.

Drive-очистка затрагивает **только** созданные этим скриптом файлы с его меткой в отдельной папке: максимум 30 копий или 200 МБ, минимум три последних. Лишние старые файлы **удаляются окончательно, без корзины**, чтобы освободить место; восстановить именно эти удалённые файлы нельзя. Остальные файлы Drive скрипт не трогает. Если загрузка или проверка нового файла не удалась, старые копии не очищаются. Для окончательного удаления скрипт обращается к Google Drive API от имени вашего аккаунта; если Google вернёт отказ, новые копии останутся, а очистка завершится ошибкой.

## Проверка и восстановление

- Раз в месяц убедитесь, что дата последней копии обновилась **в обоих местах**, и откройте JSON для проверки числа задач. Не полагайтесь только на наличие триггера: он может завершаться ошибкой.
- Восстановление выполняется вручную через «Импорт задач» в настройках веб-приложения или APK. Сначала сохраните текущие задачи отдельным экспортом, просмотрите изменения при импорте и только потом подтверждайте их. Не загружайте backup JSON на сторонние сайты.
- Сама копия сохраняет состояние на момент запуска, а не каждое изменение в реальном времени. Если задачи изменились после последнего запуска, в копии этих изменений нет.
- Код резервирования вводится в приложении только для управления копиями по HTTPS; приложение его не сохраняет. После закрытия настроек потребуется ввести его снова. Никому не передавайте код и не используйте `BLOB_READ_WRITE_TOKEN` в этом поле.
- Бесплатность зависит от текущих лимитов Vercel и Google Drive. При достижении лимита новые копии могут перестать создаваться; автоматического списания денег этот код не включает.
