# Автоматические копии задач

Vercel и Google Drive теперь независимо читают коллекцию `tasks` в Firestore. Vercel сохраняет приватный JSON в Blob по своему расписанию; личный Google Apps Script сам читает Firestore и сохраняет JSON в Drive по своему ежедневному триггеру. Drive не зависит от доступности Vercel и работает при выключенном телефоне.

Код сам по себе не включает копирование: каждое хранилище нужно настроить и проверить отдельно. До завершения этих шагов автоматических копий **нет**.

## 1. Vercel Blob

1. В проекте сайта `reminder-amber-theta.vercel.app` откройте Vercel → Storage, создайте Blob store с доступом **Private** и подключите к этому проекту. Убедитесь, что в Production появилась переменная `BLOB_READ_WRITE_TOKEN`.
2. В Settings → Environment Variables задайте `CRON_SECRET` для Production: случайная строка не короче 32 символов. Не записывайте секрет в GitHub, код, чат или публичные документы. Если переменные меняли после последнего деплоя, выполните Redeploy.
3. Убедитесь, что в Production уже существуют `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL` и `FIREBASE_PRIVATE_KEY` для проекта Firebase `reminder-60e25`. Не подменяйте их локальными/тестовыми ключами.
4. После деплоя задание `/api/cron/backup-tasks` срабатывает ежедневно около 03:00 UTC, если переключатель «Ежедневные копии Vercel» включён в настройках. Vercel сохраняет только непустую, пригодную для импорта копию и проверяет размер перед очисткой. Если число задач резко упало, старые копии не очищаются автоматически. Если `GOOGLE_BACKUP_WEBAPP_URL` уже настроен, Vercel по-прежнему посылает Drive-скрипту резервную команду на ежедневный запуск; скрипт всё равно сам читает Firestore. Новый самостоятельный Google-триггер работает даже при выключенном переключателе Vercel или его недоступности.
5. В Storage проверьте приватный файл `todo-interval/automatic/YYYY-MM-DD.json`. В журнале запуска должна быть запись об успешном вызове; HTTP 503 означает отсутствие настройки, 500 — ошибку чтения или записи. Пока не увидели настоящий файл и успешный запуск, считайте защиту **неактивной**.

Очистка Vercel затрагивает только файлы приложения с указанным именем в префиксе `todo-interval/automatic/`: максимум 30 копий или 200 МБ, но минимум три последних сохраняются даже при превышении размера. Если лимит бесплатного плана достигнут, очередная запись может не пройти — в этом случае старые копии намеренно не удаляются.

## 2. Личный Google Drive

1. Под Google-аккаунтом, которому разрешено читать Firestore проекта `reminder-60e25`, откройте [Google Apps Script](https://script.google.com/), создайте личный проект и вставьте код из [`google-drive-backup.gs`](google-drive-backup.gs) в `Code.gs`. Не делитесь редактором скрипта. Аккаунту достаточно роли `roles/datastore.viewer` (Cloud Datastore Viewer) в IAM проекта. Скрипт использует OAuth аккаунта, а не Firebase-ключ из Vercel. [Firestore REST и IAM](https://firebase.google.com/docs/firestore/use-rest-api).
2. В Project Settings включите **Show “appsscript.json” manifest file in editor**. В `appsscript.json` вставьте [`google-drive-appsscript.json`](google-drive-appsscript.json). Шаблон запрашивает права для Firestore, Drive, сетевых вызовов и установки триггера. Часовой пояс в шаблоне — `Europe/Warsaw`; при необходимости измените. [OAuth scopes Apps Script](https://developers.google.com/apps-script/concepts/scopes).
3. Запустите `backupToDrive` вручную один раз и разрешите доступ своему скрипту. При HTTP 403 проверьте IAM-роль аккаунта и разрешения скрипта; не открывайте правила Firestore всем ради копирования. Проверьте папку `To-Do Interval Backups` в Drive: откройте JSON и убедитесь, что он содержит задачи.
4. Запустите `installDailyBackup` **один раз**. Он убирает старый триггер `backupToDrive` и создаёт независимый ежедневный триггер `dailyBackupToDrive` около 04:00 по часовому поясу скрипта. Проверьте его в Triggers; на следующий день проверьте новый файл и раздел Executions. Наличие триггера само по себе не доказывает успешный бэкап. [Триггеры Apps Script](https://developers.google.com/apps-script/guides/triggers/installable).

Для самостоятельного ежедневного запуска Drive **не нужны** `BACKUP_TOKEN`, `GOOGLE_BACKUP_WEBAPP_URL` или Vercel. Если ручной вызов уже настроен, оставьте его: он продолжит поддерживать кнопку и будет запасным ежедневным запуском без дублирования файла за день. Для новой настройки ручного вызова в Script properties задайте `BACKUP_TOKEN` равным `CRON_SECRET` Vercel. Затем Deploy → New deployment → Web app: **Execute as me**, **Who has access: Anyone**. В Vercel Production добавьте `GOOGLE_BACKUP_WEBAPP_URL` с полным адресом `/exec` и сделайте Redeploy. Токен храните только в Script properties и передавайте лишь в теле POST, никогда в URL или коде. При обновлении скрипта обновите версию Web app deployment. Кнопка лишь отдаёт команду Google-скрипту: данные тот читает **напрямую из Firestore**, не скачивая Blob. «Проверить подключение» видит только URL ручного вызова, а **не** состояние Google-триггера.

Drive-очистка затрагивает **только** созданные этим скриптом файлы с его меткой в отдельной папке: максимум 30 копий или 200 МБ, минимум три последних. Лишние старые файлы **удаляются окончательно, без корзины**; восстановить именно их нельзя. Остальные файлы Drive скрипт не трогает. Если загрузка или проверка новой копии не удалась либо число задач резко упало, старые копии не очищаются. Для удаления скрипт обращается к Google Drive API от имени вашего аккаунта.

## Проверка и восстановление

- Раз в месяц убедитесь, что дата последней копии обновилась **в обоих местах**, и откройте JSON для проверки числа задач. Не полагайтесь только на наличие триггера: он может завершаться ошибкой.
- Восстановление выполняется вручную через «Импорт задач» в настройках веб-приложения или APK. Сначала сохраните текущие задачи отдельным экспортом, просмотрите изменения при импорте и только потом подтверждайте их. Не загружайте backup JSON на сторонние сайты.
- Сама копия сохраняет состояние на момент запуска, а не каждое изменение в реальном времени. Если задачи изменились после последнего запуска, в копии этих изменений нет.
- Код резервирования вводится в приложении только для управления копиями по HTTPS; приложение его не сохраняет. После закрытия настроек потребуется ввести его снова. Никому не передавайте код и не используйте `BLOB_READ_WRITE_TOKEN` в этом поле.
- Бесплатность зависит от текущих лимитов Vercel и Google Drive. При достижении лимита новые копии могут перестать создаваться; автоматического списания денег этот код не включает.
